---
title: The consent log is append only
description: Consent is recorded as events in an append-only log per channel. We never edit or delete an entry, a change is a new entry.
---

**Status:** accepted, November 2026

## Context

We must be able to show, per guest and per channel, when and how consent was given or withdrawn.

## Decision

Each entry stores the guest, hotel, channel (email, WhatsApp, later SMS), the action, a timestamp, the source and the wording version. The current state is derived from the latest entry.

## Why

- Law 2004-63 and the INPDP require clear consent, and proof is what protects the hotel.
- An editable record is not proof.
- Wording changes after legal review, so the version of the wording must be stored.

## Why not

- A boolean on the guest row: no history and no proof.

## Consequences

- Deleting a guest at their request removes the guest data, and what is kept in the log must be agreed with legal review.
- Reads need the latest entry per channel, so we keep a derived state or a query for it.

## Revisit when

Legal review changes what has to be kept or erased.
