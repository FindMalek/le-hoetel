## Environments

| Environment | How it is deployed | Notes |
|---|---|---|
| Preview | One per PR | Own database and storage prefix, log-only providers, deleted when the PR closes, with resource limits |
| Staging | Automatically from `main` | Log-only providers |
| Production | On a release | Migrations run safely first. Healthchecks, a rollback path and a short deploy note |

Previews, tests, local and staging never send real messages.

## Risks to settle

- Guest data on a self-hosted server and a home connection.
- Power and internet cuts.
- Backups: propose off-site backups for the pilot.
- Previews eating resources when many PRs are open.
- A small VPS for paying hotels would change the uptime and the hosting story.
- Hosting guest data abroad may need a legal check, see [data and consent rules](/docs/data-rules).

The choice between the self-hosted server and a small VPS for the pilot is an [open decision](/docs/decisions#open-decisions).
